# Расхождения backend с диаграммой классов

Названия классов и распределение методов между роутерами, сервисами и репозиториями
не считаются расхождением, если поведение совпадает.

1. **Пользовательская сессия и выход.** Отдельной сущности сессии и backend-метода её
   завершения нет. Вход выдаёт JWT с ограниченным сроком действия. Выход на frontend
   удаляет токен из памяти, но не отзывает ранее выданный токен на сервере. Блокировка
   пользователя проверяется при каждом защищённом запросе.
2. **Достижение цели.** Цель хранит целевую и отложенную суммы, но backend не хранит
   признак достижения и не возвращает результат отдельной проверки `достигнута`.
3. **Сумма перерасхода.** Исполнение лимита содержит сумму лимита, расходы, процент,
   статус и признак превышения, но не содержит отдельного поля с суммой перерасхода.
4. **Статус периода.** Период сохраняет месяц, сумму лимита, сумму расходов и признак
   фиксации; статус рассчитывается при чтении, а не хранится отдельным полем.
5. **Пересчёт после изменения операций.** Роутер операций напрямую не вызывает сервис
   лимитов. Незафиксированные периоды рассчитываются по текущим операциям при запросе.
   После фиксации исторического периода изменение старой операции не пересчитывает
   этот сохранённый снимок.
6. **Связь категории и лимитов.** Ограничение «до двух» выполняется для активных
   лимитов: по одному на каждую из двух валют. Архивных лимитов может быть больше.
   При удалении категории её лимиты архивируются и сохраняют историю, а ссылка на
   категорию очищается; это отличается от строгой композиции на диаграмме.
7. **Выбор категорий по виду операции.** API возвращает список категорий пользователя,
   но отдельного параметра фильтрации по типу операции не предоставляет.

Эти пункты описывают текущую реализацию; они не означают, что все отличия обязательно
нужно исправлять. Для пересчёта истории и отзыва JWT сначала нужно определить желаемые
правила поведения.
